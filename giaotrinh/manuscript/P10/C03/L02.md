Giả sử hai máy `atlas-a` và `atlas-b` phục vụ sau load balancer. Config đúng là `listen_port=8080`; service chạy dưới user `atlas`, cần quyền đọc file config và đi qua thư mục dữ liệu. Một playbook lỗi chạy `command: chmod 0700 /srv/atlas/data` ở mọi lượt rồi `notify` restart, còn task template đặt `owner: root`, `group: root`, `mode: '0600'` cho config. Trên máy chỉ cần đổi quyền thư mục, `command` vẫn có thể báo changed và kích hoạt handler không cần thiết; restart sau đó có thể khiến service user không đọc được config hoặc data. Nếu cả hai host restart cùng lúc, khả năng phục vụ có thể mất. Đây là chuỗi giả định, không phải log đã đo; `chmod` có thể thành công về exit status dù tạo quyền sai cho ứng dụng.

Phân tích theo thứ tự: xác nhận inventory thực sự chọn hai máy, connection user và `become` dùng quyền nào; xem task nào báo changed và vì sao; xác nhận mode/owner/group cùng UID/GID của service, không chỉ nhìn ký hiệu `0700` hoặc `0600`. So file trước và sau, số lần notify, điểm handler chạy, trạng thái systemd và request từ client. Nếu template bị ghi sai quyền, sửa ownership/mode trước khi restart. Dùng module `file` và `template` để hội tụ về chủ sở hữu/quyền đã kiểm tra; chỉ task đổi nội dung config mới notify handler `ansible.builtin.systemd_service` với `state: restarted` khi ứng dụng thực sự cần đọc lại config. Task bảo đảm service đang chạy dùng `state: started`, không dùng `restarted` ở mọi lượt. Với nhiều máy, dùng nhóm thử trước rồi `serial: 1` hoặc chiến lược phù hợp, rút từng máy khỏi lưu lượng nếu cần và kiểm tra request đại diện trước máy tiếp theo. `serial: 1` giới hạn số host trong một batch, không tự rút lưu lượng hoặc bảo đảm health check đúng.

Một sửa đổi an toàn bắt đầu từ backup cấu hình và đường khôi phục, kiểm tra syntax của cấu hình bằng chính ứng dụng nếu nó có chế độ validate đáng tin, kiểm tra quyền file và dữ liệu, rồi mới restart. Nếu validate task thất bại, không nên ghi đè file tốt hoặc gọi handler. Sau restart, kiểm tra tiến trình, log, cổng lắng nghe và request qua đúng load balancer; trạng thái `active` của systemd chỉ là một phần bằng chứng. Khi một host lỗi giữa play, các task đã hoàn tất trên host khác không tự rollback. Ghi lại host nào đã đổi nội dung, host nào mới sửa quyền, handler nào đã chạy và phiên bản config hiện tại; khoanh tác động rồi phục hồi từng host theo trạng thái thực. Secrets trong biến, template và diff cần được quản lý bằng cơ chế bảo mật riêng, không đặt mật khẩu vào inventory Git hay in diff/log.
