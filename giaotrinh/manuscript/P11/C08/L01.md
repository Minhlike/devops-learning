Một YAML render sạch chỉ cho ta biết phép thay biến đã tạo văn bản hợp cú pháp. Nó chưa nói API server có CRD, controller có hiểu Route hay client có tới đúng listener. Với Helm, tôi theo một release bằng những dấu mốc tách biệt: Chart/Values → template → manifest → API → controller → workload → request thật. Nếu dừng ở mốc đầu rồi bảo “đã triển khai”, ta đang gọi bản thiết kế là công trình đã mở cửa.

Một chart là gói đầu vào. `Chart.yaml` có tên và chart version; `values.yaml` chứa mặc định; `templates/` là Go template được render với values hiệu lực. Giá trị do người dùng truyền qua `-f` hoặc `--set` có thể ghi đè mặc định; khi upgrade, `--reuse-values` còn có thể mang một override từ revision trước. Cùng một template vì thế cho manifest khác nhau. Render cục bộ không thử quyền API, CRD, Gateway controller hoặc DNS. Đừng đổ lỗi controller trước khi biết Helm đã gửi **manifest nào**.

Chart `atlas-gateway` chỉ tạo Gateway và HTTPRoute trong namespace release, trỏ Service `atlas:80` của {{xref:P11.C02.L02}}. Ví dụ chưa chạy trên cluster. Muốn thử trong nơi được phép, cần Gateway API CRD, GatewayClass `example-gateway` có controller thật, namespace `demo`, Service `atlas` và backend Ready. `example-gateway` không phải class mặc định của Kubernetes. Manifest ở {{xref:P11.C02.L02}} không gắn namespace; nếu dùng lab cô lập, `kubectl -n demo apply -f` với đường tệp ấy chỉ sau khi hiểu và sửa hai lỗi cố ý trên **bản sao thử**, không áp nó vào workload đang phục vụ.

Với Helm 3, `helm lint` và `helm template atlas-edge ./examples/gateway-helm --namespace demo` kiểm chart và hiện manifest dự kiến. Đổi hostname bằng values file thử, rồi so `metadata.namespace=demo`, `atlas-edge-web`, listener `http`, host và backend. Nếu cluster được phép triển khai, lần lượt xem GatewayClass Accepted, Gateway/listener Programmed, HTTPRoute parent Accepted/ResolvedRefs, địa chỉ Gateway, DNS, rồi request với `Host: atlas.example.test` từ client xác định. Không tự cài CRD/controller hoặc dựng Gateway ngoài môi trường được giao chỉ để làm đẹp ví dụ.

Một case **giả định** giải thích vì sao phải ghi values hiệu lực. Chart mặc định `hostname: atlas.example.test`, nhưng revision 4 từng được cài với `hostname: old.example.test`. Revision 5 dùng chart mới cùng `--reuse-values` mà không truyền host mới, nên override cũ có thể tiếp tục đi vào manifest. “Source chart đã sửa” lúc này là sự thật không đủ. Ghi chart version/digest, các file `-f` theo thứ tự, `--set`, chế độ reuse/reset và values cuối; so `helm template` từ đúng đầu vào với `helm get manifest` của revision sau triển khai. `helm get values --all` cho thấy values tính cả mặc định, còn manifest nói trường Kubernetes thực được gửi. Trên bản sao chart không chứa secret, render mặc định, override bằng file và override dòng lệnh; nếu listener và Route lấy host từ hai key khác nhau, YAML vẫn hợp cú pháp mà request có thể không khớp. Phép thử này xác nhận template, chưa xác nhận controller hoặc DNS.
